# HTML-презентация для выступления

Runtime-презентация из каталога `in/`: HTML читает `slide.md` и медиафайлы напрямую при открытии.

**Формат входных данных:** [IN_FORMAT.md](IN_FORMAT.md) — требования к `slide.md` и медиафайлам.

**Для AI-агента из другого проекта:** [README_for_agents.md](README_for_agents.md) — как подготовить **один** `slide.md` на проект.

## Быстрый старт

Откройте `index.html` в браузере, нажмите **F11** для полноэкранного режима.

Если файл открыт локально через `file://`, браузер не разрешает HTML самостоятельно сканировать папки. На стартовом экране нажмите **«Выбрать каталог in/»** и выберите папку `in/` или корень репозитория. При открытии через обычный HTTP-сервер или GitHub Pages каталог читается автоматически.

**Онлайн:** https://timptr42.github.io/show/

Навигация: клик по правой половине экрана / кликер — вперёд, левая половина — назад. Стрелки на клавиатуре тоже работают.

## Структура `in/`

| Папка | Назначение |
|-------|------------|
| `00-welcome` | Приветствие: заголовок из frontmatter, фоновые видео из папки |
| `01-…` … `NN-…` | Блоки выступления (`type: talk`) |
| `99-questions` | Финальный экран |

В каждом блоке — **`slide.md`**. Каждый заголовок `##` — отдельный слайд (порядок как в файле). Медиа подключаются ссылками `![](file.png)` или тегом `<video>`; неиспользованные файлы из папки попадают на демо-слайды после секции `## Демо`.

Подробности — в [IN_FORMAT.md](IN_FORMAT.md).

## Как это теперь работает

- `index.html` лежит в корне и не содержит заранее скомпилированного списка слайдов.
- При загрузке HTML читает все папки из `in/`, парсит каждый `slide.md` и подставляет медиа из той же папки.
- Чтобы добавить или заменить документ, достаточно изменить содержимое `in/` и перезагрузить страницу.
- `python3 build.py` оставлен только как совместимость: он копирует runtime HTML в `out/index.html`, но не компилирует слайды и не копирует медиа.

GitHub Pages публикует репозиторий как статический сайт, чтобы `index.html` и `in/` были доступны рядом друг с другом (см. `.github/workflows/pages.yml`).
