# Формат входных данных (`in/`)

`index.html` читает каталог `in/` напрямую в браузере при открытии страницы.

**Правило:** в презентацию попадает то, что описано в `slide.md` и лежит в каталоге блока. Заглушки и синтетические медиа **не создаются**.

---

## Структура каталога

```
in/
  00-welcome/          # экран приветствия
  01-…/                  # блок выступления
  02-…/
  …
  99-questions/          # финальный экран
```

| Элемент | Обязательность |
|---------|----------------|
| Папка блока | одна на слайд-группу, имя с префиксом `NN-` для сортировки |
| `slide.md` | **обязателен** в каждой папке |
| Медиафайлы | рядом с `slide.md` (в корне папки блока) |

Подпапки (`demo/`, `assets/`) не сканируются автоматически — в `slide.md` указывайте путь относительно папки блока; HTML ищет файл по пути и по имени (`assets/scheme.svg` → `scheme.svg`).

---

## Frontmatter

YAML в начале `slide.md`:

```yaml
---
title: "Заголовок блока"
author: "Имя · команда"      # для type: talk
subtitle: "Подзаголовок"     # для welcome / questions
type: talk                   # talk | welcome | questions
---
```

| `type` | Назначение |
|--------|------------|
| `welcome` | первый экран, фоновые видео из папки |
| `talk` | блок доклада |
| `questions` | финальный экран |

---

## Как `slide.md` задаёт слайды

### Блок `type: talk`

1. Текст **до первого** `##` — опциональное **вступление** (отдельный слайд).
2. Каждый заголовок `## …` — **один слайд** (или группа демо), **в порядке следования в файле**.
3. Имена секций произвольные; типичный набор:

```markdown
## Проблематика
## Инструменты
## Решение
## Демо
## Вопросы?
```

4. Содержимое секции — обычный Markdown (абзацы, списки, таблицы, **ссылки на медиа**).

### Секция `## Демо`

- Текст секции — вводный абзац на **первом** демо-слайде.
- Медиа указывайте **явно** в секции (каждый файл — отдельный демо-слайд):
  - `![](demo-01.png)` — изображение
  - `<video src="demo-01.mp4" controls playsinline preload="metadata"></video>` — видео
  - `- \`demo-01.gif\`` — строка со именем файла
- Порядок слайдов — как строки в `## Демо`.
- Файлы из папки, не перечисленные в MD, добавляются в конец демо автоматически.

### Блоки `welcome` и `questions`

- **welcome:** заголовок и подзаголовок — из frontmatter; фон — секция `## Фон` или все видео в папке.
- **questions** (`99-questions`): на экране только крупный **`?`** по центру поверх фонового видео; в frontmatter достаточно `title: "?"`, секция `## Фон` — список роликов.

### Секция `## Вопросы?` в блоке `talk`

Заголовок секции **не менять**. Внутри — **только один символ** `?` (отдельной строкой):

```markdown
## Вопросы?

?
```

На слайде отображается крупный **`?`** по центру; списки вопросов в MD не нужны.

## Ссылки на медиа

### Markdown-картинки

```markdown
![Описание схемы](scheme.svg)
![Скрин](demo-02.png)
```

Путь — относительно папки блока. Допустимы префиксы `assets/`, `videos/` (файл ищется и там, и по имени в корне).

### HTML (видео)

```html
<video src="01-collections.mp4" controls width="960" poster="01-collections.png"></video>
```

### Список файлов в обратных кавычках

Строки вида `- \`demo-01.gif\`` автоматически превращаются в картинки на слайде.

### Внешние URL

`https://…` в Markdown-ссылках не копируются, остаются как есть.

## Требования к медиафайлам

| Формат | Расширения | Где используется |
|--------|------------|------------------|
| Изображения | `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.svg` | внутри секций или демо-слайды |
| Видео | `.mp4`, `.webm`, `.mov`, `.m4v` | секции, демо, фон welcome/questions |

Рекомендации:

- **Схемы:** SVG или PNG, читаемые с расстояния; в MD — `![](scheme.svg)`.
- **Демо-скрины:** `demo-01.png`, `demo-02.png`, … — удобные имена для секции `## Демо`.
- **Демо-видео:** `demo-01.mp4`; в презентации **без автозапуска** (управление Play).
- **Фон welcome:** положите ролики в `in/00-welcome/` (любые имена).
- Имена файлов лучше без пробелов; регистр в Windows не важен, в git — важен.

Если в MD указан файл, которого нет в папке, HTML **пропустит** эту ссылку и выведет предупреждение в консоль браузера.

---

## Что runtime HTML не делает

`python3 build.py` теперь не собирает слайды. Он только копирует runtime HTML в `out/index.html` для старых сценариев запуска.

Сам HTML:

- не создаёт placeholder-видео и пустые картинки;
- не подмешивает медиа из других блоков;
- не сканирует подпапки без ссылки в MD (кроме поиска по имени файла там, где браузер может перечислить каталог);
- не меняет содержимое `in/`.

---

## Проверка перед выступлением

Откройте `index.html` и перезагрузите страницу после изменений в `in/`.

Если открываете локальный файл через `file://`, выберите папку `in/` на стартовом экране. Предупреждения о пропущенных ссылках смотрите в консоли браузера.
